> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 v1 的 4 个分散 Steam 假入库工具合并成一个统一 GUI（入库中心.exe），带 4 个 tab、快照式备份回滚、游戏检索，且不改动任何 v1 运行副本。

**Architecture:** 复制 v1 的 4 个已验证 Python 模块（`auto_adapt` / `version_lock` / `apply_patch` / `denuvo_helper`）到 v2 的 `src\`，做最小改造解除硬编码；新建 `paths.py`（路径与账号解析）、`backup.py`（快照/回滚/体检/审计）、`game_index.py`（名字检索）、`main_app.py`（tkinter 统一 GUI）；最后 PyInstaller onefile 打包。GUI 通过函数级调用复用模块，用 `threading` + 回调把进度写回界面。

**Tech Stack:** Python 3.14.7 + tkinter 9.0（内置）、PyInstaller 6.22.3、pytest（仅开发期测试，不打包）、标准库 `urllib`/`winreg`/`zipfile`/`hashlib`。

**Spec:** `D:\STEAM入库\全自动入库_v2\docs\superpowers\specs\2026-11-23-入库中心v2-design.md`（含附录 A 的 10 条澄清；A3/A4 已由用户定稿）

## Global Constraints

- **不动 v1 运行副本**：`D:\STEAM入库\全自动入库\`、`D:\STEAM\` 全程只读。所有写入只在 `D:\STEAM入库\全自动入库_v2\`。

以下 5 类输入/失败模式是 spec 隐含但任务测试最易漏掉的，各在拥有该代码的任务里钉一条测试：

2. **网络不可达时入库/检索不能卡死或崩** —— 代理/超时环境（历史代理 `proxy-china-prod-dku.oit.duke.edu:3128` 已设 None，但仍可能失败）。→ Task 2 测 `fetch_app_info` 超时降级；Task 3 测 storesearch 失败返回空列表不抛异常。

5. **key 库缺失/损坏时不能联网重下 16MB 卡死** —— 历史上移动目录后找不到 key 库导致卡在"联网解析中"。→ Task 2 测 resource_dir 定位优先级；key 库不存在时 `get_key_db` 返回空 dict 并报明确错误，不触发下载。
