# 入库中心 v2 设计（借鉴 TitanCore 的产品化设计）

日期：2026-11-23
状态：已批准（用户 2026-11-23 批准；3 项偏好已定稿，见附录 A3/A4；下一步进入实现计划）

## 1. 意图与为什么

用户要把现有的、分散的 Steam 假入库工具，进化成一个统一、安全、可维护的工具。
借鉴对象是 TitanCore（tc.modvips.com / GitHub）的产品化设计，但**只借设计思路，不借代码**：

- TitanCore 开源仓库只有 GUI 外壳（Electron+Vue）和注入胶水（`native/tc_native.cc`）；
  真正干活的入库/密钥/版本逻辑在其服务端 API + TCDB 数据库 + 闭源 core DLL，拿不到。
- 用户现有的核心逻辑（4 个 Python 模块）已经过实战验证（剑星 v1.4.1 全程跑通），重写风险远大于收益。

## 2. 目标（Goals）

1. **统一入口**：一个 `入库中心.exe`，用 tab 分区，合并现在分散的 4 个入口
   （`简单入库.exe`、`导入破解包.bat`、`导入补丁包.bat`、`OST管理面板.bat`）。
2. **复用已验证逻辑**：4 个核心模块 `auto_adapt` / `version_lock` / `apply_patch` / `denuvo_helper`
   原样复用，只做最小改造。
3. **快照式备份回滚**：把现在散装的 `ost_deploy_backup` 快照，做成规范化的一键备份 / 一键回滚 / 操作审计。
4. **游戏检索**：输入游戏名或 AppID 入库；本地名字缓存 + 联网 storesearch 补查。
5. **不动运行副本**：产物放新目录 `D:\STEAM入库\全自动入库_v2\`，v1（`全自动入库`）与 `D:\STEAM` 保持原样，验证通过再切。

## 3. 非目标（Non-goals / Anti-goals）

- **改"来自家庭库"的显示 / 正版联机**：这是 Steam 服务器账本的判定，本地工具改不了。
  之前切 huanyuejue fork 试图本地清共享标记，结果是假下载（0 文件 commit），已证伪，不再尝试。
- **Denuvo 破解自动化**：提票（`extract_tickets`，票据 30 分钟有效）/ 打补丁必须人工，
  现有 `denuvo_helper` 做到"检测+指路+票据槽位"就是上限。
- **云存档 / 创意工坊 / 挂卡 / ASF**：与用户场景无关，不碰。
- **Electron+Vue 全重写**：npm 调用异常、核心逻辑仍要回 Python、工作量最大、易翻车。
- **改 v1 运行副本**：v2 是独立新目录，与 v1 共存。

## 4. 约束（Constraints）

| 项 | 现状 |
|---|---|
| 语言/运行时 | Python 3.14.7 + tkinter 9.0（内置可用） |
| 打包 | PyInstaller 6.22.3，沿用 `--onefile --windowed` 流程 |
| 编译器 | 无 cmake / cl / msbuild / gcc → 写不了 native 注入 DLL |
| Node | node v24.20.0 有，但 npm/npx 调用异常 → Electron 路线放弃 |
| v1 模块硬编码 | `简单入库.py:13`、`version_lock.py:27` 写死 `LUA_PATH = r"D:\STEAM\config\stplug-in\mygames.lua"`；`auto_adapt.py` 用 `HERE` |
| 游戏名数据 | `auto_adapt_cache.json` 仅 10 条名字；`depotkeys_master.json` 28.8 万条 key 但无游戏名 |
| Steam 版本 | 11.23.65.88；登录过 3 个账号；星痕 localconfig 有 FamilyGroup/SharedAuth 标记 |

## 5. 方案对比（Approaches）

**A. 就地升级 Python + tkinter（选中）**
把 4 个模块复制进 v2，外面套一个统一 tkinter GUI，做最小改造解除硬编码。
- 收益：改动最小、逻辑复用、双击 exe 的使用习惯不变、风险最低。
- 代价：界面观感一般（tkinter 原生控件）。
- 选型理由：核心逻辑已是 Python 且验证过；界面丑可以渐进升级，逻辑重写没有收益。

**B. Python 后端 + 本地浏览器界面（弃）**
逻辑仍是 Python，GUI 换成本地网页（如 Flask + HTML）。
- 收益：界面能做得现代。
- 代价：要先起服务再开浏览器，使用方式改变；多一层进程和端口管理；对用户是净负担。

**C. Electron + Vue 全重写（弃）**
TitanCore 同款技术栈。
- 收益：最漂亮、产品化最强。
- 代价：npm 环境异常、核心逻辑仍要回 Python（多语言桥接）、工作量最大、易翻车。

## 6. 设计（Design）

### 6.1 产物目录

```
D:\STEAM入库\全自动入库_v2\
├── 入库中心.exe              # 唯一入口（PyInstaller onefile）
├── docs\superpowers\specs\   # 本设计文档
├── src\
│   ├── main_app.py           # 统一 GUI（tab 布局）
│   ├── paths.py              # 集中路径解析：Steam 目录 / lua 路径 / v2 数据目录（无硬编码常量）
│   ├── backup.py             # 新建：快照 / 回滚 / 审计（见 6.4）
│   ├── game_index.py         # 新建：名字缓存 + storesearch 补查（见 6.5）
│   ├── auto_adapt.py         # 复制自 v1，最小改造：HERE/LUA 路径改为从 paths 注入
│   ├── version_lock.py       # 复制自 v1，最小改造：LUA_PATH 从 paths 注入
│   ├── apply_patch.py        # 复制自 v1（本身已用注册表+盘符探测，基本无需改）
│   ├── denuvo_helper.py      # 复制自 v1，最小改造：LUA_PATH 从 paths 注入
│   ├── depotkeys_master.json # 复制自 v1（16MB，28.8 万条）
│   ├── crack_library.json    # 复制自 v1
│   └── auto_adapt_cache.json # 复制自 v1
├── snapshots\                # 备份快照存放（见 6.4）
└── audit.log                 # 操作审计日志
```

### 6.2 GUI 布局（4 个 tab）

文本草图（批准后可做可点击原型）：

```
┌──────────────────────────────────────────────┐
│  入库中心 v2            [Steam 状态: 运行中]   │
├────────┬────────┬────────┬───────────────────┤
│ 入库   │ 版本锁定│ 补丁   │ 备份与隔离         │
├────────┴────────┴────────┴───────────────────┤
│ [游戏名/AppID 输入 ______] [添加入库]          │
│ 状态: ✓ 已入库 3489700 Stellar Blade          │
│ ┌─ 已入库游戏列表 ────────────────────────┐   │
│ │ 550  Left 4 Dead 2                      │   │
│ │ 3489700  Stellar Blade (已打补丁)        │   │
│ └────────────────────────────────────────┘   │
│ [刷新] [移除选中] [刷新Key库] [搜索游戏...]    │
└──────────────────────────────────────────────┘
```

- **入库 tab**：现有 `简单入库.py` 全部功能 + 游戏检索框（6.5）+ 可下载/可运行/可联机三态提示。
- **版本锁定 tab**：包办 `version_lock.py` 的 plan / --import / --lock；显示破解库、锁定 GID、下一步指引（关 Steam → 删 appinfo.vdf → 冷启动 → 核对 Downloading GID）。
- **补丁 tab**：包办 `apply_patch.py` 的扫描 / 覆盖 / 备份 / dry-run。
- **备份与隔离 tab**：快照列表 / 一键备份 / 一键回滚 / 配置体检 / 操作审计（6.4）。

### 6.3 模块复用与小改造

- 4 个模块**复制**进 `src\`（不动 v1 原件）。
- 新建一个 `paths.py` 集中解析路径：
  - `find_steam_dir()`：环境变量 `STEAM_PATH` → 注册表 `HKCU\Software\Valve\Steam\SteamPath` → 常见盘符 → 报错。
  - `lua_path()`：`<steam>\config\stplug-in\mygames.lua`。
  - `app_dir()`：frozen 时用 `dirname(sys.executable)`，源码时用 `dirname(__file__)`（数据文件定位）。
- 把 `简单入库.py` / `version_lock.py` / `denuvo_helper.py` 里模块级的
  `LUA_PATH = r"D:\STEAM\..."` 改成从 `paths.lua_path()` 取值；`auto_adapt.py` 的 `HERE` 改成 `paths.app_dir()`。
- 这些改造只在 v2 副本上做，v1 运行副本零改动。

### 6.4 账号隔离与备份回滚（"轻量隔离"的落地定义）

**能治的**：污染主号、翻车难还原。
**治不了的**（写进界面提示）："来自家庭库"的显示 / 正版联机。

机制：
1. **快照对象**（可勾选）：
   - `D:\STEAM\config\config.vdf`
   - `D:\STEAM\config\loginusers.vdf`
   - `D:\STEAM\userdata\<当前账号>\config\localconfig.vdf`
   - `D:\STEAM\config\stplug-in\mygames.lua`
   - `D:\STEAM\opensteamtool.toml`
2. **一键备份**：把选中文件连同时间戳复制进 `snapshots\<YYYYMMDD_HHMMSS>\`，写一份 `manifest.json`（原路径、sha256、大小）。
3. **一键回滚**：从选中快照按 manifest 逐文件还原，还原前再给当前状态打一个"回滚前"快照（防止回滚本身误操作）。
4. **配置体检**：只读扫描并提示——是否存在 FamilyGroup/SharedAuth 标记、mygames.lua 块是否配对完整（OSTBLOCK/ENDMARK 数量）、三件套 DLL 哈希是否匹配已知正常值。
5. **操作审计**：每次入库 / 锁定 / 打补丁 / 备份 / 回滚，往 `audit.log` 追加一行（时间、动作、AppID、改动文件路径）。

这是"快照式隔离"：不做独立 Steam 配置目录（那需要复制整套 Steam 或用 `-nohome` + 符号链接，太重且易碎），而是靠"操作前留底 + 一键还原"达到同等的安全效果。

### 6.5 游戏检索

- 本地名字缓存 `names.json`（新建，初值为 `auto_adapt_cache.json` 里的 10 条）。
- 输入时先本地模糊匹配（子串 / 拼音首字母暂不做），命中即列出候选。
- 本地没有则联网 `store.steampowered.com/api/storesearch?term=<关键词>&l=schinese&cc=cn` 补查，
  把结果（AppID + 名字）追加进 `names.json` 持久化。
- 联网失败时静默降级为"仅本地匹配"，不阻塞入库主流程。
- 入库后把该游戏名字写回缓存。

### 6.6 打包

- PyInstaller `--noconfirm --clean --onefile --windowed --name "入库中心"`。
- 注意（踩坑经验）：
  - PowerShell 会把 PyInstaller stderr 的 INFO 当异常 → 用 `$ErrorActionPreference='Continue'` + `*>&1` 捕获。
  - 冒烟测试要等约 12 秒（5 秒不够），检查 `Responding=True` 和窗口标题。
  - 旧 exe 进程占用导致复制失败 → 用"重命名旧 exe + 复制新 exe"绕过，或先 Stop-Process。

## 7. 交给 builder 的自由项（已由我定，可在文档评审时否决）

- GUI 用 tkinter 原生控件，不引入第三方主题库（减少依赖与打包体积）。
- `names.json` 初值只放现有 10 条，靠使用过程逐步积累，不预先爬全量游戏名。
- 快照默认勾选全部 5 类对象；回滚永远先打"回滚前快照"。
- 配置体检的 DLL 正常哈希取当前实测值（dwmapi FE82F35C… / xinput 0234A56A… / OpenSteamTool 705B31DC…）。

## 8. 验收标准（供实现计划拆解）

1. 双击 `入库中心.exe` 能打开，4 个 tab 都在，无报错。
2. 入库 tab：输入 `550` → 能解析、写入 mygames.lua、列表刷新；重复添加不产生重复块（幂等）。
3. 版本锁定 tab：能列出破解库 1 条（剑星）；能对剑星给出锁定 GID 指引。
4. 补丁 tab：能对 `_crack_ready` 做 dry-run 扫描并列文件。
5. 备份与隔离 tab：一键备份生成快照+manifest，一键回滚能还原，体检能报告块配对/DLL 哈希。
6. 游戏检索：输入"剑星"或"Stellar"能命中 3489700（本地或联网）。
7. v1 运行副本（`全自动入库`、`D:\STEAM`）在本 v2 全流程中未被改动（哈希/时间戳比对）。

## 附录 A：builder 审查回应与设计澄清

独立 builder 审查后提出 10 个问题。以下逐条澄清；其中标 **[待用户确认]** 的 3 条已一并提交用户拍板。

**A1. 4 模块集成方式（问题 1）**
已读全部 v1 源码：4 个模块都是「函数 + argparse + `if __name__=='__main__'`」组织，核心逻辑是函数级
（`auto_adapt.build_block/fetch_app_info/judge`、`version_lock.plan/do_lock/do_import`、`apply_patch.apply/dry_run`、`denuvo_helper.denuvo_plan`）。
GUI 用 **函数级直接调用 + `threading` 线程** 集成，不走 subprocess；进度/异常通过回调写回 GUI 状态栏。
只改路径注入，不改函数签名，保证「原样复用」。

**A2. Denuvo 边界（问题 2）**
v2 的 Denuvo 助手只做「检测 + 指路 + 生成 `setAppTicket` 槽位注释」写进 lua。
不做实际提票（本机无 `extract_tickets`）、不做票据导入、不做 30 分钟有效期校验——这些必须人工。
剑星这类「纯单机 Denuvo」走补丁 tab（补丁自带 steam_api64 emu，不依赖票据）。

**A3. 当前账号判定（问题 3）[已定稿：自动认当前 + 下拉可切]**
自动检测当前账号（注册表 `AutoLoginUser` + `loginusers.vdf` 的 SteamID64→accountid 映射），
界面显示当前账号 + 下拉可切换到本机其他已登录账号（本机 3 个：星痕 monstercaatt / smallmonstercat / ittllou）。
备份回滚针对选中账号的 `localconfig.vdf`。

**A4. 备份/回滚一致性与并发（问题 4）[已定稿：回滚前强制退 Steam]**
备份 = 只读复制、**不要求退出 Steam**（快照取当前磁盘状态，快）；
回滚 = **强制要求先退出 Steam**：检测到 Steam 进程运行就提示并中止回滚，退出后重试；
回滚前自动再打一份快照；manifest 校验失败则中止回滚并提示；单用户工具，不做文件锁。

**A5. 补丁输入约定（问题 5）**
补丁 tab 用目录/zip 选择器，默认指向 `D:\STEAM入库\剑星+破解补丁\_crack_ready\`，可改；
`apply_patch.py` 的 `appid / patch / --game-dir / --dry-run` 调用契约不变。

**A6. 版本锁定 tab 数据流（问题 6）**
薄封装现有 CLI：

- 列表 = 读 `crack_library.json`（当前剑星 1 条）+ 显示其 `locked_gids`
- 写锁定块 = 调 `version_lock.do_lock(appid)` 写 mygames.lua
- 导入破解包 = 调 `do_import` 从 zip 提取 GID 写 `crack_library.json`
- 下一步指引 = 固定文案（关 Steam → 删 appinfo.vdf → 冷启动 → 核对 Downloading GID）

**A7. 联网检索验收口径（问题 7）**
本地 `names.json` 预置 10 条（含剑星/Stellar，满足验收第 6 条）；联网 storesearch 作为增强
（`store.steampowered.com/api/...` 已验证可达），`urllib` + 5 秒超时，失败静默降级为仅本地匹配。
验收以本地命中为准，联网为锦上添花，不作为必测项。

**A8. DLL 哈希基准（问题 8）**
完整路径 `D:\STEAM\dwmapi.dll` / `xinput1_4.dll` / `OpenSteamTool.dll`，精确匹配**完整 SHA256**
（dwmapi `FE82F35C02CB81FEBF070EF3B9194FF5D52EE526608BF3DE76D09E04C5B20DF1` /
xinput `0234A56A72121FD3DD50FF533F1A6E670033DBC2D92EF98551E8903CFF402250` /
OpenSteamTool `705B31DC1C0335F5519BCB938ED589BA6909F3AAB6B7B89495C1569A951210D5`）。
做成「已知哈希列表」（允许追加多个，Steam 更新后可扩），体检报告「匹配 / 不匹配 + 当前哈希」，不硬编码单一值误报。

**A9. onefile 数据文件位置（问题 9）**
`paths.py` 区分两个目录：
- `resource_dir()`：只读随包资源（`depotkeys_master.json` / `crack_library.json`），frozen 时为 `sys._MEIPASS`，源码时为 `src/`，用 `--add-data` 打包
- `writable_dir()`：运行时可写数据（`names.json` / `snapshots\` / `audit.log` / `auto_adapt_cache.json`），frozen 时为 exe 同目录，源码时为 `src/`

**A10. 三态提示判定（问题 10）**
复用 `auto_adapt.judge()` 现有判定，纯展示不改逻辑：
可下载 = key 库命中（has_key）；可运行 = 无 Denuvo 或 `crack_library` 有 verified 补丁；可联机 = judge 的 online_part（非自有账号/非反作弊）。
界面标注「仅本地判断，不代表 Steam 服务器认可」。
