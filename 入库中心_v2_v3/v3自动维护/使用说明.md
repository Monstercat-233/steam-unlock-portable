# 入库中心 v2（接入启动自检）使用说明

日期：2026-11-23　适用：`D:\STEAM入库\全自动入库_v2\入库中心.exe`（SHA256 `CCFC2BAD9D56E93B16FDF60B835DA9D5D5803CF2E9A1A40356E3200CCDD4CB56`）

## 1. 本次新增：启动自检做什么

双击 `入库中心.exe` 后，后台线程自动跑一次**只读**版本自检（`update_guard`）：

- **读**：Steam 的 `appmanifest_<appid>.acf`、`libraryfolders.vdf`，以及随包 `crack_library.json` 中已验证（`verified=true`）且带 `locked_gids` 的锁定游戏。
- **写**：仅为尚无基线的锁定游戏生成/补全 `baseline.json`（原子落盘）。其他文件一概不写。
- **判**：把当前 `buildid` / `TargetBuildID` / 每个锁定 depot 的 `manifest GID` 与基线比对。
- **结果**：
  - 无变化 → 「版本锁定」tab 顶部标签显示一行提示「（启动自检完成，已锁定游戏版本正常）」，**不弹窗**；
  - 有变化 → 该标签显示红色多行告警，并弹出标题「本体版本变化」的警告框，文案给出 buildid 变化 / TargetBuildID 待更新 / depot manifest 变化的具体差异及处置建议。

**不做**（明确边界）：不自动刷新 GID、不自动下载补丁、不修改游戏文件、不碰 v1 运行副本、不常驻后台、不改系统设置。自检在 daemon 线程执行，UI 不卡；即便自检出错也有异常兜底弹窗（`版本自检失败: ...`），不影响主界面其它功能。

## 2. baseline.json 是什么 / 怎么重建

- 位置：frozen 模式落在 **exe 同级**目录，即 `D:\STEAM入库\全自动入库_v2\baseline.json`（源码模式在 `src\`）。
- 内容：每个锁定游戏一条，记录 `name` / `buildid` / `target_buildid` / `manifest_gids` / `captured_at`。例：剑星 3489700 基线 buildid=26123051，3 个 GID（3489701/3596180/3596190）。
- 首次启动自动生成；已有条目非强制模式保留，不会被覆盖——这是防止「更新后被静默重锁」的关键。
- 想重新采集基线（例如你已手动重锁重打、确认当前版本就是新基准）：**关闭入库中心 → 删除 `baseline.json` → 重新启动 exe**，自检会按当前已锁定游戏与 ACF 重写一份。删基线不会动任何游戏文件。

## 3. 看到「本体版本变化」告警怎么办

告警含义：Steam 下发了本体更新（buildid 变 / TargetBuildID≠buildid / depot manifest GID 变），现有补丁很可能失效，**确认前不要启动游戏**。处置流程：

1. 打开入库中心「版本锁定」tab，对告警里的游戏（如剑星 3489700）**重新锁定**（重锁会刷新 locked_gids）。
2. 到「补丁」tab **重新下载**对应补丁并**重新打补丁**。
3. 关闭并重启入库中心，再删一次 `baseline.json` 重建基线（否则旧基线仍会报变化）。
4. 重启后再看自检是否不再弹窗，确认无变化后再启动游戏。

## 4. 回退步骤（一键还原到接入自检前的 v2）

备份在 `D:\STEAM入库\全自动入库_v3\integration_backup\`，`backup_hashes.txt` 记录原始 size/sha256。

1. **关闭入库中心**（含残留进程；任务管理器确认无 `入库中心.exe` / `RukuCenter.exe`）。
2. 用 `integration_backup\main_app.py` 覆盖 `D:\STEAM入库\全自动入库_v2\src\main_app.py`（原件 SHA256 `BB3829E57E9D1A3683A1A57AC2C26032C690C66C5223D3FED0BC951B3E87FDE2`）。
3. 用 `integration_backup\入库中心.exe` 覆盖 `D:\STEAM入库\全自动入库_v2\入库中心.exe`（原件 SHA256 `8B162D1F5AB5290BED637419D23E2CE8C45ECFEB2660DDECEBE88622C1598916`）。
4. 可删除 `D:\STEAM入库\全自动入库_v2\src\update_guard.py` 与 `v2\baseline.json`（回退后不再使用；保留也无害）。
5. 重新启动 exe 验证回退生效。

如需彻底回退到未打包状态，只需上述覆盖；backups 原件哈希已复核一致，可直接用。

## 5. 打包说明（维护者）

- 打包命令在 v2 目录执行（勿用 `build.ps1`，中文路径会被 PowerShell 读坏）：
  `$env:PYTHONUTF8=1; cd D:\STEAM入库\全自动入库_v2; C:\Python314\python.exe -m PyInstaller RukuCenter.spec --noconfirm`
- 产物 `dist\RukuCenter.exe` 复制到 v2 根目录改名 `入库中心.exe`。spec 里 `name='RukuCenter'` 保持英文（中文 `--name` 会失败）。
- 随包数据：`depotkeys_master.json` / `crack_library.json` / `names.json` 可独立更新，无需重打包。
