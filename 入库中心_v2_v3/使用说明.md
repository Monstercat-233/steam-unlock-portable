# Steam 入库管家 · 使用说明

借鉴 TitanCore 设计的本地入库工具。单 exe、零硬编码路径（自动找 Steam）、4 个 tab 一站式操作，零中心化服务、零遥测。

## 快速开始

双击 `入库管家.exe`。程序自动定位 Steam 目录和当前登录账号（下拉可切换）。

## 界面与主题

界面基于 **pywebview 6.2.1 + 系统自带 WebView2**（前端是单文件 HTML/CSS，Python 后端通过 `js_api` 桥调用），业务逻辑与 v1 完全同源，只换了外观。WebView2 运行时由 Windows 10/11 自带，exe 不额外打包浏览器内核。

- **顶栏**：左侧图标 + 「入库中心 / OpenSteamTool 全自动 · v2」双行标题；右侧依次是当前账号 chip、Steam 运行状态 chip（绿点=运行中 / 灰点=未运行）、主题下拉。
- **主题**：默认「深色 · Midnight」，内置 4 套 —— 深色 · Midnight / 浅色 · Daylight / 深色 · Nord / 浅色 · Solarized。切换即时生效，无需重启。
- **主题记忆**：选择写进 exe 同目录的 `ui_prefs.json`（源码模式写 `src\`），下次启动自动恢复；想重置直接删这个文件。
- **布局**：顶栏 + 左侧 186px 导航（4 个 tab，带序号和功能图标）+ 主面板 + 底部状态栏。主面板统一「卡片（细线边框 + 圆角）+ 表格（斑马纹、表头浅底）+ 状态行」三段式；窄窗口下主面板独立滚动，状态栏与导航始终可见。
- **配色语义**：状态文字按含义着色 —— 灰=中性提示 / 蓝=进行中 / 绿=成功 / 黄=需注意 / 红=失败；按钮：蓝=主操作（入库、应用锁定、确认覆盖、立即备份）、描边=次操作（刷新、扫描预览、浏览…、体检）、红=破坏性操作（移除选中、回滚到选中快照）。
- **图标**：`app.ico` 由 `main_app.py` 内嵌的 64×64 PNG 生成，打包时嵌入 exe；界面里的 logo 是内联 SVG，无外部图片依赖。
- **字体**：统一 `Microsoft YaHei UI`，路径/日志用 `Consolas`，高 DPI 自适应（WebView2 按系统缩放渲染）。
- **错误日志**：`--windowed` 打包后没有控制台，任何未捕获异常都会写进 exe 同目录的 `ui_error.log`（正常情况下该文件只记录启动信息）。

## 游戏封面卡片

「入库清单」和「搜索结果」从纯文字表格升级为**封面卡片墙**：每张卡片上方是 Steam 商店横版封面（`header.jpg`，约 16:7），下方是游戏名与 AppID；窗口变窄时自动换行。

- **来源**：Steam 官方 CDN（`shared.fastly.steamstatic.com` 优先，失败自动切 `cdn.cloudflare.steamstatic.com`），按 AppID 请求，8 秒超时；首次打开并发 6 线程拉取，之后直接读本地缓存。
- **缓存**：exe 同目录的 `covers\<AppID>.jpg`（源码模式写 `src\covers\`）。删掉该目录即可重新下载；离线机器也可预先拷入这个目录直接显示。
- **占位图**：DLC 或部分 AppID 没有 header.jpg，卡片显示灰色手柄占位图，名字、AppID 与全部操作照常可用。
- **交互**：搜索结果卡片点「选用」或双击 → 填入 AppID；入库清单卡片点击选中（高亮）→ 配合「移除选中」使用。

## 游戏名称与来源识别

「入库清单」现在会直接从 `mygames.lua` 的 `#OSTBLOCK` 注释里读出游戏名，不再只依赖 `names.json`，所以以前显示「未命名」的游戏绝大多数都能正确显示名字（如「求生之路2」「黑神话悟空」「剑星 / Stellar Blade」）。若注释里只有一串数字 AppID，会依次回退到 `names.json`、`Steam appmanifest` 里的正式名称；仍取不到时才显示 `AppID xxxxx`，不再出现「未命名」。

每张入库卡片左上角另有一个来源徽章，用来区分这个 AppID 是你 Steam 账号本来就拥有的，还是仅通过本工具解锁入库的：

- <span style="color:#3fb950">**绿色「Steam 已拥有」**</span>：Steam 的 `libraryfolders.vdf` / `appmanifest_*.acf` 里存在该 AppID（本机原本就有）。
- <span style="color:#d29922">**橙色「工具入库」**</span>：只有 `mygames.lua` 块、Steam 清单里查不到（由本工具解锁/添加）。
- 卡片名下方的小字是块注释里的适配来源（如「全自动适配」「key 库无记录，仅显示图标」「版本锁定：GUI 应用锁定」）。
- 卡片列表上方有来源筛选：**全部 / Steam 已拥有 / 工具入库**，右侧计数实时显示两类各多少个。

来源只读取本机 Steam 数据做判断，不联网、不写 Steam 目录。判断依据是"该 AppID 是否出现在 Steam 库清单文件里"，对应的是"这个库文件夹当前登记的游戏"，不等同于账号维度的永久拥有历史；换电脑或库文件夹后会重新判定。

## 四个 tab

### 1. 入库
- 输入游戏名 / AppID / 商店链接 → 点「搜索名字」→ 下方结果卡片双击（或点卡片内「选用」）填入 AppID → 点「+ 入库」；也可直接输数字 AppID 跳过搜索。
- 「刷新」重读 `mygames.lua` 并刷新封面卡片；「移除选中」删掉选中的入库块；「打开目录」跳到 `mygames.lua` 所在目录。
- 状态栏三态：
  - 绿=可下载+可运行（老 SteamStub 单机/纯合作 PVE）
  - 黄=需票据/补丁（Denuvo 游戏，见「版本锁定」tab）
  - 红=仅显示图标（key 库无 depot key，下载不了）
- 下载后若提示「内容配置无效」：关 Steam → 删 `D:\STEAM\appcache\appinfo.vdf` → 重开 Steam（注入层改 GID 后必须冷启动才生效）。

### 2. 版本锁定（给破解游戏锁老版本）
- 「破解库」表格列已知 Denuvo 游戏，列为 AppID / 名称 / 锁定 GID。
- 「应用锁定到入库清单」把该游戏的 manifest GID 换成破解版锁定值。
- **导入破解包**：在「破解包路径」框粘贴单个**锁定版 lua**（破解包里带 `setManifestid` 的那个 .lua）路径，或点「浏览…」选它（也支持 zip / 目录）；再点「导入破解包」。工具从 lua 里挖出 locked_gids 写进 `mygames.lua`，并把补丁文件暂存到 `patches\`。注意：只给一个普通 `3489700.lua`（只有 `addappid`、没有 `setManifestid`）挖不到 GID，必须传**锁定版** lua。
- **一键冷启动（关 Steam → 关自动更新 → 清缓存 → 重开）**：点一下自动完成「关 Steam（含 webhelper/crashhandler）→ 把已锁定游戏的 `AutoUpdateBehavior`/`ScheduledAutoUpdate` 归零（改前备份 appmanifest）→ 备份并删 `appinfo.vdf` + `appcache\appinfo` 目录 → 冷启动 Steam」，不用自己删文件。备份落在 `backup\`，状态行会显示关了哪些游戏的自动更新、备份路径和新 Steam PID。改 GID / 导入破解包 / 切注入后必须用它才生效。
  - ★ **换账号登录后 Steam 会把 `AutoUpdateBehavior` 同步回 1**，触发校验清掉破解 emu dll、游戏打不开。遇到这情况点「一键冷启动」即可自动归零修复；也可在「应用补丁」tab 重新覆盖补丁补回 dll。
- 「刷新破解库」重读 `crack_library.json`。
- 固定版本标准流程（界面内「固定版本操作指引」4 步）：①导入破解包 →「应用锁定」；②点「一键冷启动」（自动清缓存）；③核对 `content_log` 的 `Downloading ... (锁定 GID)` 并等下载完；④到「应用补丁」tab 覆盖补丁、关 Steam 直接运行游戏验证。
- ⚠ `setManifestid` 第一参数必须是数字，写成字符串会被 Steam 静默忽略（v1 踩过的坑，v2 已修正）。

### 3. 补丁（打破解补丁）
- 填 AppID + 补丁包路径（`_crack_ready` 目录或 zip），补丁包可点「浏览…」选。
- 游戏目录可留空（自动按 Steam 库查找），也可手填。
- 「扫描预览 (dry-run)」在下方「待覆盖文件」表格列出将覆盖哪些文件（目标相对路径 / 来源文件），**只读不写**。
- 确认无误后「确认覆盖」，覆盖前自动备份到游戏目录 `_patch_backup\<appid>_<时间>\`。

### 4. 备份与隔离（轻量）
- 账号下拉默认认当前登录，可切换。
- 「立即备份所选账号配置」备份 config.vdf / loginusers.vdf / localconfig.vdf / mygames.lua / opensteamtool.toml + manifest.json。
- 「配置体检」显示：是否家庭共享、lua 块是否配对、三 DLL 哈希是否正常。
- 「刷新快照列表」重读快照表（类型 / 快照目录）。
- 「回滚到选中快照」从快照还原——**强制要求先退出 Steam**，否则拒绝（防占用写坏）。
- 所有操作写 `audit.log`，并在「输出 / 最近审计」卡片里回显。

## 关于「账号隔离」的实话

假入库游戏显示「来自家庭库」是 Steam **服务端账本**判定，本地工具改不了。此处的「轻量隔离」=独立配置快照 + 干净基线 + 一键回滚（翻车秒还原、不污染主号），**不改变显示**。之前试过本地清共享标记的 fork，结果是假下载（0 文件），已证伪。

## 数据与更新

- `depotkeys_master.json`（16MB / 288381 条）：depot 解密 key 库，与 exe 分开存放，可单独替换更新。
- `crack_library.json`：破解游戏库（GID 锁定值）。
- `names.json`：游戏名↔AppID 本地索引，联网查询后自动写回。
- 这 3 个文件放在 exe 同级目录即可被读取；源码模式下在 `src\`。
- `ui_prefs.json`（运行时自动生成）：记住上次选的主题，删掉即恢复默认「深色 · Midnight」。
- `ui_error.log`（运行时自动生成）：界面层异常日志，排查白屏/报错时先看它。
- `covers\`（运行时自动生成）：每个 AppID 一张 Steam 横版封面 jpg，删掉即重新下载；可预先拷入实现离线显示。
- `audit.log`、`baseline.json`、`auto_adapt_cache.json`、`snapshots\`：机器私有运行数据，**不要随包分发**。

## 已知边界

- Steam 大版本更新后 OST 的 hook pattern 需上游跟上（联网自动拉），期间入库功能可能短暂失效；已落盘游戏/补丁不受影响。
- SteamTools 与 OST 二选一，不能共存（都劫持 `xinput1_4.dll`）。
- 只适用于无反作弊 / 纯单机 / Steamworks 票据可解的游戏；EA/Ubisoft/Xbox Live 自有账号 + 内核反作弊游戏无解。
- 破解游戏建议关闭自动更新，否则本体更新会让锁定 GID 失效。

## 数据与更新补充说明

本目录即完整可运行产品；exe 同级保留 `depotkeys_master.json` / `crack_library.json` / `names.json` 时优先读取（便于单独更新 key 库），不打也能跑（已内嵌进 exe）。所有机器私有数据（备份 / 缓存 / 日志）都在运行时生成于 exe 同级，不随包分发。
