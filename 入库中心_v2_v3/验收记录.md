## 冒烟方式（pywebview 与 tkinter 的差异）

- 窗口类名是 `WindowsForms10.Window.8.app.*.r21_ad1`（不是 tkinter 的 `TkTopLevel`），按标题枚举时必须同时匹配类名前缀，否则会误命中残留的旧窗口。
- onefile 父进程无窗口，`subprocess.communicate()` 会一直挂住 → 用文件重定向 + `taskkill /IM …/T/F` 收尾，不要等 `communicate()`。
- 抓图继续用 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` + `GetDIBits(BGRA)`（WebView2 有效，且不受 z-order 遮挡）；必须等窗口拿到真实尺寸（>300px）再抓。
- `RESPONDING` 必须在 `kill` **之前**采样（先 kill 再判一定 False）。
- 每轮实测：`WINDOW_IN ≈ 1.06s`（tkinter 版 1.51s），`IS_CHILD True`，`WINDOWS_LEFT 0`。

## 踩到的坑（已修）

**js_api 公开属性会被 pywebview 递归扫描。** 首版把窗口句柄挂在 `Bridge.window`（公开属性），`webview/util.py::get_functions()` 会 `for name in dir(obj)` 递归遍历所有非下划线属性，于是递归进 `window.native.AccessibilityObject.Bounds.Empty.Empty…` 造成 `maximum recursion depth exceeded`，随后 `CoreWebView2Controller members can only be accessed from the UI thread`，`finish_script` 注入失败 → 前端收不到 `pywebviewready` → 白屏 + 窗口「未响应」。改为 `Bridge._window` 后立刻正常。此约束已写进 `Bridge` 的 docstring。
